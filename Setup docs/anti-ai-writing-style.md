# Anti-AI-Writing-Style

Owner's writing preferences. When writing in this project — daily reports,
code comments, judge-facing copy, project documents — the following patterns
must be **avoided**.

## Banned words and phrases

- "delve"
- "it is worth noting that…"
- "in conclusion"
- "I would like to point out…"
- "It is important to note that…"
- "Certainly!"
- "Of course!"
- "Great question!"
- "I'd be happy to…"
- "Hope this helps!"
- "Let me…"
- "Let's dive in…"
- "Firstly, secondly, thirdly…"
- "navigate the complexities of…"
- "in today's fast-paced world…"
- "ever-evolving landscape…"
- "revolutionize" / "game-changing" (esp. in judge-facing copy)

## Banned structures

- Lists of three that exist for rhetorical effect (not when the three are factual).
- Marketing-tone summaries at the end of an answer.
- "Conclusion" sections that re-state the body.
- Em-dashes used as a substitute for "and" / "but" three or more times in one paragraph.

## Banned tones

- Corporate hedging ("it could potentially be argued that…").
- Apologetic preamble before a substantive answer.
- Cheerleading ("Great work!" / "Excellent!").

## Voice rules (positive)

- Short, direct sentences. One idea per sentence.
- Active voice.
- Past tense for completed work, present tense for current state.
- For technical documents: code-first where possible.
- For judge-facing copy: claims carry evidence links, hedges carry reasons.

> Maintenance: every time a new banned pattern is identified, append it here
> and reference the daily-report date where it was first observed.
